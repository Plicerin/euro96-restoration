# Browser proof of concept

The `browser-proof` branch builds the existing C++ restoration with Emscripten and SDL 3.4.18. The immutable Windows baseline is `v0.70.0-final` (`a2e7cdd`). No native playtest package or launcher has been replaced. This preview preserves the current 4:3 presentation; widescreen and HD rendering are future work.

## Run locally

Run `tools/play_web.ps1`, or the separate `Play-Euro96-Web.cmd` in the parent outputs folder. The launcher starts a hidden Python server bound only to `127.0.0.1`, reuses it when already running, and opens `http://127.0.0.1:8786/`. The URL must be served over HTTP; opening index.html as a file does not work.

Choose **Play Euro 96** for the original menus, or **Watch CPU vs CPU** for a match. The launch click enables sound. Focus the game canvas for keyboard controls. Use the page's Fullscreen button; P pauses/resumes. Real focus loss pauses a match and clears held input.

Preferences, championship checkpoints/backups and saved replays are restored from `/saves` in IndexedDB before main() runs. The page reports pending, successful and failed persistence separately from the game's filesystem save message, with a retry button on failure. Saves are specific to browser profile and origin (scheme/host/port). Keep the same address. Clearing site data removes them. The Windows save directory is not accessed.

## Build

Verified toolchain: Emscripten **6.0.12**, SDL **3.4.18**, CMake **4.3.1**, Ninja, host Python. CMake's warning about shared Wasm libraries does not apply here: SDL is built statically.

Install the official Emscripten SDK in a folder with several GiB of free space:

```powershell
git clone --depth 1 https://github.com/emscripten-core/emsdk.git D:/Codex/euro96-web/emsdk
cd D:/Codex/euro96-web/emsdk
./emsdk.bat install 6.0.12
./emsdk.bat activate 6.0.12
```

Download/extract the official SDL3-3.4.18 source release to `D:/Codex/euro96-web/SDL3-3.4.18`. From this repository:

```powershell
./tools/build_web.ps1
./tools/test_web.ps1
./tools/play_web.ps1
```

Each script accepts directory overrides. The build script requires the restored local retail media and stages an explicit allowlist, never user saves. Output is `D:/Codex/euro96-web/build/site` by default. No SDK or compiled media is committed to Git.

The preview carries 30 verified asset files (107,450,731 bytes, 102.47 MiB): original archives, all eight Euro venues, player graphics, pitch sounds, menu music and English commentary. The module is approximately 3.3 MiB plus 275 KiB of JavaScript. Each asset is size/SHA-256 checked before use. Trophy films, animated menu previews, French commentary and older Actua compatibility packs are excluded. This is still a relatively large initial load; progressive packs/compression remain follow-up work.

## Port adaptations

- Browser-only CMake configuration compiles SDL from source, enables exceptions and an expandable Wasm heap, and omits DLL packaging. Original SOURCE files are untouched.
- Asyncify preserves the existing stack-owned application lifetime while `emscripten_sleep(16)` returns control to the browser between frames. Gameplay remains on its existing fixed-step clock. SDL's implicit Asyncify yields are disabled to avoid suspension inside renderer/audio operations.
- The browser links a small adapter implementing the frozen Windows restoration's MSVC rand/srand sequence. Wasm libc has a different sequence; without the adapter, the held-input automatic-selection contract failed. This matches the Windows restoration's RNG, not a claim of exact retail Watcom RNG reproduction.
- Generated byte-immediate action/message IDs now have integer C++ types. This fixes Clang's rejection of a floating-point switch label without changing the recovered values.
- Browser saves use explicit asynchronous IndexedDB flushes after completed file replacements. Native save behavior is unchanged.

## Verification — 2026-10-16

- WebAssembly: all four existing contract suites pass. Ball suite: 72,185 checks. Selection: 32 kickoff configurations, both pitch halves, held input and two full human-control simulations. Regulation: twelve complete CPU matches. Penalties: twelve human shootouts plus aim/charge/cancellation checks.
- Windows: eight focused tests passed after rebuilding: frontend contracts/smoke, tournament contracts/save-directory/recovery, match settings, replay serialization and replay-file smoke. Restoration tooling: 12 tests passed.
- Chromium: verified asset loading, original menus, exhibition startup, active CPU play, keyboard input, pause, fullscreen entry/exit, preferences reload, championship creation/resume, Sim Next completing and saving one fixture, and saved replay creation/reload/playback.
- Audio: Web Audio reached the running state after the launch click; sampled actual output was nonzero (peak approximately 0.117). This is signal verification, not a subjective listening certification.
- Injected an IndexedDB flush failure: the page displayed its failure state, and Retry save successfully persisted the pending changes.
- Compared twelve Windows/Wasm seeded match summaries. All completed and passed contracts, but seven had different tick/event summaries. Cross-compiler floating-point/library behavior remains a possible source; exact lockstep determinism is **not** established. This port does not implement network multiplayer.

## Remaining browser work

This is a local proof, not a completed browser release. Physical gamepads/two-controller play, Firefox/Safari, mobile/touch controls, sustained performance and public hosting are unverified. There are two known development-console messages: SDL's initial swap-interval request expects a callback main loop, and Chromium deprecates SDL's ScriptProcessorNode audio backend. The game currently drives its frames explicitly and audio output is verified; a callback-based application loop and a newer browser audio path are follow-up work.

Replace Asyncify with an owned application-state/frame callback after parity checks, add save export/import and versioned download caching, then use the desktop/browser foundation for widescreen and a shared HD renderer. Assets and binaries are not deployed publicly by these scripts.
